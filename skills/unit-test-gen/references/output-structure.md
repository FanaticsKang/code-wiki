# 输出目录结构

技能产出分两个目录：**工作目录**（用户看）和**调试目录**（Claude 内部）。

---

## 工作目录 `test/generated_unit/`

用户直接打开、提交、查看的东西。清爽、无中间产物。

```
test/generated_unit/
├── test_cases.json              # 基线文件（元数据 + MD5 + cases 描述，不含测试代码）
├── report.md                    # 测试报告
├── _helpers.py                  # Python 测试辅助（若仓库含 Python）
├── _helpers.hpp                 # C++ 测试辅助（若仓库含 C++）
├── conftest.py                  # pytest 路径配置（自动生成）
├── core/
│   ├── test_parser.py           # Python 测试（对应 Python 源码）
│   └── test_calculator.cpp      # C++ 测试（对应 C++ 源码）
├── utils/
│   └── test_format.py
└── api/
    └── test_handlers.py
```

## 调试目录 `.test/generated_unit/`

脚本的中间产物、Claude 调试用的原始数据。`.` 开头使其自动被扫描规则和常见
工具（git、编辑器）忽略。**不应提交到版本库**，建议加入 `.gitignore`。

```
.test/generated_unit/
├── scan_result.json             # scanner 原始 stdout（仅在怀疑扫描问题时手动生成）
├── coverage.json                # pytest-cov 原始报告（Python）
├── coverage.info                # lcov 原始数据（C++）
├── failures.json                # 失败用例详情（Claude 用于修复循环）
└── *.gcda / *.gcno              # gcov 中间文件（C++）
```

---

## 目录分工原则

| 文件类型 | 位置 | 理由 |
|---------|------|------|
| 基线（`test_cases.json`） | 工作目录 | 用户可能编辑 `coverage_config`，需要可见 |
| 测试代码、测试辅助 | 工作目录 | 最终产物，用户执行和审阅 |
| 报告（`report.md`） | 工作目录 | 最终产物 |
| 覆盖率原始数据 | 调试目录 | 中间产物，用完即可删 |
| 失败详情 `failures.json` | 调试目录 | Claude 内部用 |
| scanner stdout 副本 | 调试目录 | 排障产物，默认不生成 |

混合语言仓库中，不同语言的测试文件共存于同一目录结构下。各语言有自己的辅助
文件（如 Python 的 `_helpers.py`、C++ 的 `_helpers.hpp`）。

---

## 命名规则

源码 `src/<path>/<n>.<ext>` → 测试 `test/generated_unit/<path>/test_<n>.<ext>`。

例子：
- `src/core/parser.py` → `test/generated_unit/core/test_parser.py`
- `src/utils/Format.cpp` → `test/generated_unit/utils/test_Format.cpp`

## 测试文件头注释

每个生成的测试文件顶部加注释：

```
AUTO-GENERATED by unit-test-gen skill. DO NOT EDIT.
Source: src/core/parser.py
Regenerate with: /unit-test-gen auto
```
