# 覆盖率与 Dead Code 检测

覆盖率收集与 dead code 检测在 `run` 阶段执行。本文档讲**语言无关**的配置、判定规则和策略。
各语言的具体工具命令、输出解析见 `language-python.md` 和 `language-cpp.md`。

---

## 覆盖率配置

配置存储在 `test_cases.json` 的 `coverage_config` 字段。用户可手动编辑该文件调整配置。
首次运行时如果该字段不存在，使用默认值。字段含义和默认值详见
[`test-cases-schema.md`](test-cases-schema.md) 的 `coverage_config` 小节。

## 三种覆盖率指标

| 指标 | 含义 | Python 工具 | C++ 工具 |
|------|------|------------|---------|
| 语句覆盖率 | 被执行到的代码语句占比 | `pytest-cov`（`coverage.py`） | `gcov` + `lcov` |
| 函数覆盖率 | 被调用到的函数占比 | `pytest-cov` | `gcov` + `lcov` |
| 分支覆盖率 | if/else 等分支被走过的占比 | `pytest-cov --cov-branch` | `gcov` + `lcov` |

## 阈值判定规则

- 三种指标各自独立判定达标/未达标
- 未达标的文件和模块在报告中高亮标注
- 同时给出未达标原因分析（哪些函数/分支未被覆盖）

## 未达标时的原因分析

对覆盖率未达标的模块/文件，在报告中给出：

- 具体哪些函数未被调用（列出函数名）
- 具体哪些分支未被走过（如未触发的 if/else 分支、异常处理分支）
- 原因归类：依赖外部上下文、mock 难度高、需要真实环境等

## Dead Code 检测

### 检测工具

| 语言 | 工具 | 安装方式 |
|------|------|---------|
| Python | `vulture` | `pip install vulture` |
| C++ | `cppcheck` / 编译器 `-Wunused-function` | 系统包管理器 |

### 检测流程

1. 在测试执行和覆盖率收集**之后**，对源码目录运行静态分析
2. 读取 `coverage_config.dead_code_min_confidence` 作为置信度阈值（默认 80）
3. 按语言执行静态分析（具体命令见对应语言参考文档）
4. 过滤已知误报：入口函数、CLI handler、动态调用、反射调用、注册机制回调等
5. 与覆盖率 0% 的函数列表交叉验证，两处都标记的优先级更高

### 局限性

- 静态分析存在误报（动态调用、反射、插件注册、虚函数回调等）
- 报告中统一标注为「dead code 候选项」，建议用户复核后决定是否删除
- 不同语言的具体误报模式见对应语言参考文档
