# 报告格式说明

写入 `test/generated_unit/report.md`，每次 `run` 命令覆盖写入。

### 未达标模块分析

#### core/dag/
- 语句覆盖率 45%（阈值 70%）：主要未覆盖文件为 `sub_dag_node.py`（8%）、`master_node.py`（11%）
- 函数覆盖率 52%（阈值 70%）：`sub_dag_node.py` 中 15/20 个函数未被测试调用
- 分支覆盖率 31%（阈值 60%）：`dag_executor.py` 的异常处理分支均未触发
- 原因分析：子 DAG 执行流程依赖完整流水线上下文，mock 难度较高

## 字段说明

### 头部元信息

| 字段 | 来源 |
|------|------|
| 日期 | `run` 执行时刻 |
| 模式 | `init` 时的 `--mode` 参数 |
| 语言 | `test_cases.json` 的 `languages` + `test_frameworks` |
| 扫描范围 | `test_cases.json` 的 `source_dirs` |
| 函数覆盖 | 已测函数数 / 扫描到的函数总数 |

### 执行摘要

| 字段 | 含义 |
|------|------|
| 总测试数 | 本次执行的测试用例总数 |
| 通过 | 断言全部通过的用例数 |
| 失败 | 断言失败的用例数（预期行为与实际不符） |
| 错误 | 测试执行过程中抛出未捕获异常的用例数 |
| 跳过 | 因环境缺失等原因跳过的用例数（需附理由） |
| 耗时 | 测试执行总耗时 |
| 通过率 | (通过 / 总测试数) × 100% |

### 增量信息

仅在增量模式下显示。全量模式省略此节。

### 未通过用例

标题以**源码位置**开头（`source_file:line — function_name`），而非测试名。
便于快速定位实际出错的源码位置。

失败类型分为三类：

| 类型 | 判定方式 |
|------|---------|
| 断言失败 | traceback 含 `AssertionError` 且有 `E   AssertionError` 模式 |
| 执行异常 | 其他未捕获异常 |
| fixture 错误 | 来自 ERRORS section（测试未实际执行） |

### 跳过用例详情

列出所有被跳过的测试及其原因。仅在存在跳过用例时显示。

### 测试结果概览

按文件分组展示通过率，`[PASS]` 表示全部通过，`[FAIL]` 表示有失败。

### 生成/更新文件

列出本次 `generate` 阶段新增或更新的测试文件。
