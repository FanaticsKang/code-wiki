# 报告格式说明

写入 `test/generated_unit/report.md`，每次 `run` 命令覆盖写入。

## 模板

```markdown
# 单元测试报告

| 项目 | 值 |
|------|-----|
| 日期 | 2026-04-16 12:34 |
| 模式 | incremental |
| 语言 | Python (pytest) |
| 扫描范围 | src/ |
| 函数覆盖 | 187 / 187 (100%) |

## 执行摘要

| 指标 | 值 |
|------|-----|
| 总测试数 | 612 |
| 通过 | 598 |
| 失败 | 10 |
| 错误 | 2 |
| 跳过 | 2 |
| 耗时 | 12.3s |
| 通过率 | 97.7% |

## 增量信息（增量模式时显示）

| 指标 | 值 |
|------|-----|
| 文件级变更 | 3 |
| 函数级变更 | 12 |
| 新增函数 | 5 |
| 删除函数 | 2 |
| 未变更跳过 | 170 |

## 失败用例

### test_core_parser.py::test_parse_header_exception_truncated

- 函数：`parse_header`
- 维度：异常容错
- 失败原因：`AssertionError: expected ValueError but got IndexError`
- 判定：可能是源码 bug，建议 review `src/core/parser.py:23`

## 生成/更新文件

- test/generated_unit/core/test_parser.py（更新）
- test/generated_unit/utils/test_format.py（新增）
```

## 字段说明

### 头部元信息

| 字段 | 来源 |
|------|------|
| 日期 | `run` 执行时刻 |
| 模式 | `init` 时的 `--mode` 参数 |
| 语言 | `test_cases.json` 的 `languages` + `test_frameworks` |
| 扫描范围 | `test_cases.json` 的 `source_dirs` |
| 函数覆盖 | 已测函数数 / 扫描到的函数总数 |

### 执行摘要

| 字段 | 含义 |
|------|------|
| 总测试数 | 本次执行的测试用例总数 |
| 通过 | 断言全部通过的用例数 |
| 失败 | 断言失败的用例数（预期行为与实际不符） |
| 错误 | 测试执行过程中抛出未捕获异常的用例数 |
| 跳过 | 因环境缺失等原因跳过的用例数（需附理由） |
| 耗时 | 测试执行总耗时 |
| 通过率 | (通过 / 总测试数) × 100% |

### 增量信息

仅在增量模式下显示。全量模式省略此节。

### 失败用例

每个失败/错误的用例单独一节，包含：

| 字段 | 说明 |
|------|------|
| 测试标识 | 文件名 + `::` + 测试函数名 |
| 函数 | 被测函数名 |
| 维度 | 所属测试维度 |
| 失败原因 | 断言失败的原始错误信息 |
| 判定 | `测试代码问题`（需修正测试）或 `疑似源码 bug`（附建议 review 位置） |

### 生成/更新文件

列出本次 `generate` 阶段新增或更新的测试文件，标注状态（新增 / 更新）。
